## 一、地图：Lyra 的六层抽象

Lyra 的所有系统可以画成一张**六层架构图**。这张图是整个 Wiki 的"总设计图"，贴到你的笔记本封面上每天看一遍。

```
┌───────────────────────────────────────────────────────────────┐
│ [6] UI 层 (CommonUI / HUD / Widget)                           │
│   - LyraHUD / LyraActivatableWidget                           │
├───────────────────────────────────────────────────────────────┤
│ [5] 玩家输入层 (Enhanced Input)                                │
│   - LyraInputConfig / InputAction / InputMappingContext       │
├───────────────────────────────────────────────────────────────┤
│ [4] 能力层 (GAS - Gameplay Ability System)                    │
│   - LyraGameplayAbility / AttributeSet / GameplayEffect       │
├───────────────────────────────────────────────────────────────┤
│ [3] 角色/装备层                                                │
│   - LyraCharacter / LyraPawnData / Equipment / Weapon         │
├───────────────────────────────────────────────────────────────┤
│ [2] 装配层 (Experience + Game Features) ★ Lyra 的灵魂          │
│   - LyraExperienceDefinition + GameFeatureAction              │
├───────────────────────────────────────────────────────────────┤
│ [1] 框架层 (GameMode / GameState / PlayerController)           │
│   - LyraGameMode / LyraGameState (UE 原生骨架)                │
└───────────────────────────────────────────────────────────────┘
```

**从下往上读**：

- **[1] 框架层** —— 标准 UE 套路，和你写过的任何 UE 项目一样。`GameMode` 负责服务端流程，`GameState` 保存全局同步状态，`PlayerController` 管每个玩家的输入。
- **[2] 装配层** —— 本项目的"灵魂"。当你启动一局游戏时，框架层并不直接写死"生成什么 Pawn、给什么能力、显示什么 UI"，而是去读一个**配置文件（Experience）**，由配置文件决定一切。这一层是 Lyra 区别于普通项目的关键。
- **[3] 角色/装备层** —— 什么角色能被选中、角色身上能挂什么武器。
- **[4] 能力层** —— 射击、冲刺、跳跃这些"动作"都是 **Ability**，血量、弹药这些"数值"都是 **Attribute**。用 GAS 统一处理。
- **[5] 玩家输入层** —— UE 5 的 Enhanced Input 系统。把按键和能力"缝"在一起。
- **[6] UI 层** —— 基于 CommonUI。现代化的 UE UI 框架，支持键鼠/手柄/触屏一致体验。

**读代码时的定位习惯**：每次打开一个新类，先问自己"这个类在哪一层？"。答不出来就说明你没看懂它存在的意义，去找它的上下层关系。

## 二、15 个核心术语

下面这些词在 Lyra 代码里每天见。按重要程度排序，前 5 个必须**倒背如流**。

### ★★★★★ Experience（体验 / 经验）

**Lyra 最核心的概念**。一个 `Experience` 就是**"一局游戏"的配置清单**：

- 用什么 Pawn？
- 加载哪些 Game Feature 插件？
- 启用哪些输入映射？
- 显示什么 HUD？
- 给玩家默认什么能力？

类：[LyraExperienceDefinition](../Source/LyraGame/GameModes/LyraExperienceDefinition.h)

**举例**：Lyra 主菜单有三个按钮 "射击" / "TopDown Arena" / "训练场"。每个按钮背后就对应一个 Experience 资产。点哪个按钮，就加载哪个 Experience，游戏就"变"成那个玩法。

**类比**：把 Experience 想成**一份餐单**。你不是直接告诉厨房"做个汉堡"，而是把"汉堡套餐 #3"这个单子递进去，单子上写着用什么面包、什么牛肉、什么酱料。

### ★★★★★ GameFeature（游戏功能插件）

UE 原生的"可插拔插件"机制，Lyra 把它用到极致。

一个 GameFeature 是一个**独立的插件**，里面装了一组资源（蓝图、输入配置、UI、C++ 模块）。可以在运行时**动态激活/卸载**。

- 激活时：自动把内容"注入"当前世界（加能力、加 UI、绑输入）。
- 卸载时：自动清理干净。

路径：[Plugins/GameFeatures/](../Plugins/GameFeatures/)

Lyra 自带的 GameFeature：

- `ShooterCore` —— 射击玩法核心。
- `ShooterMaps` —— 射击关卡。
- `TopDownArena` —— 俯视角竞技场。

**Experience 和 GameFeature 的关系**：一个 Experience 会声明"我需要激活哪些 GameFeature"。加载 Experience 时，这些 GameFeature 会自动激活。

### ★★★★★ GameplayTag（游戏标签）

UE 原生特性。一串层级化的字符串，比如 `"Ability.Movement.Sprint"` 或 `"Status.Death"`。

在 Lyra 里，GameplayTag 是**系统之间的通用语言**：

- 能力用 Tag 标识自己（"这是一个移动能力"）。
- 角色用 Tag 标识状态（"我正在死亡"）。
- UI 用 Tag 决定显示什么。
- 消息系统用 Tag 路由事件。

文件：[LyraGameplayTags.h](../Source/LyraGame/LyraGameplayTags.h) / [Config/DefaultGameplayTags.ini](../Config/DefaultGameplayTags.ini)

**为什么重要**：Lyra 几乎所有"解耦"都靠 Tag 完成。两个系统不需要互相认识，只要都读/写同一个 Tag 就能通信。

**心法 2 再强调**：**GameplayTag 是导航仪**。找不到谁在动什么，就全局搜那个 Tag。

### ★★★★★ Ability（能力）

GAS 里的核心概念。一个 `Ability` 代表一个**"可以做的动作"**：跳跃、冲刺、开火、换弹、甚至"死亡流程"。

Ability **不是**一个简单的函数调用。它有：

- 激活条件（Cost / Cooldown / Tag 要求）
- 激活流程（可以异步，可以跨帧）
- 取消条件
- 网络复制行为

类：[LyraGameplayAbility](../Source/LyraGame/AbilitySystem/Abilities/LyraGameplayAbility.h)

**举例**：开火是一个 Ability。按下开火键 → `TryActivateAbility` → 检查弹药（Cost）→ 检查冷却（Cooldown）→ 播放开火动画 → 射线检测 → 应用伤害 Effect → 结束 Ability。

### ★★★★★ AttributeSet（属性集）

GAS 概念。一个 C++ 类，声明一组**会被网络同步的数值属性**：

```cpp
// LyraHealthSet 举例
UPROPERTY(BlueprintReadOnly, Category = "Lyra|Health", ReplicatedUsing = OnRep_Health)
FGameplayAttributeData Health;
```

Attribute 不是普通 float。它有：

- 自动网络复制。
- 可以被 GameplayEffect 修改（加减乘除）。
- 可以有"当前值 vs 基础值"两个值（比如护甲加成可以临时提高 MaxHealth）。

核心文件：[LyraAttributeSet.h](../Source/LyraGame/AbilitySystem/Attributes/LyraAttributeSet.h) 及子类 `LyraHealthSet` / `LyraCombatSet`。

### ★★★★ PawnData（角色数据资产）

一个数据资产，声明"**这种角色长什么样**"：

- 用什么 PawnClass（类）？
- 默认有哪些能力（AbilitySet 列表）？
- 用什么相机模式？
- 用什么输入配置？

类：[LyraPawnData](../Source/LyraGame/Character/LyraPawnData.h)

**和 Experience 的关系**：Experience 里会引用一个默认 PawnData（`DefaultPawnData`），表示"这种 Experience 下玩家默认用什么角色"。

**类比**：PawnData 是**角色档案卡**。Experience 是**剧本**，它在剧本里写"主角用档案卡 #7"。

### ★★★★ GameplayEffect（效果）

GAS 概念。一个数据资产，描述**"一次属性修改"**：

- 减 10 点血（瞬时 Effect）。
- 每秒烧 2 点血，持续 5 秒（Duration Effect）。
- 眩晕期间禁用移动（Infinite Effect + Tag）。

Effect 是 **GAS 里对数值进行修改的唯一合法手段**。你不会看到 Lyra 直接 `Health -= 10`，而是 `ApplyGameplayEffect(DamageEffect)`。

为什么？因为 Effect 是数据驱动、可叠加、可回滚、可网络同步的。

### ★★★★ AbilitySystemComponent (ASC)

GAS 的"总控制器"组件。每个需要用 GAS 的 Actor 身上挂一个。

它负责：

- 激活/结束 Abilities。
- 持有 Attributes。
- 应用/移除 Effects。
- 同步 GameplayTags。

Lyra 扩展版：[LyraAbilitySystemComponent](../Source/LyraGame/AbilitySystem/LyraAbilitySystemComponent.h)

**Lyra 的关键设计**：ASC 挂在 **PlayerState** 上而不是 Pawn 上。这样玩家死亡重生时 ASC 不会被销毁重建，能力、冷却、属性都能延续。

### ★★★★ AbilitySet（能力包）

**Lyra 独创**。一个数据资产，**把 Abilities + GameplayEffects + AttributeSets 打包**，方便一次性授予给 ASC。

类：[LyraAbilitySet](../Source/LyraGame/AbilitySystem/LyraAbilitySet.h)

**举例**：`AS_HeroDefault` 可能打包了：

- 能力：跳跃、冲刺、开火、换弹。
- 属性集：HealthSet、CombatSet。
- 效果：初始护盾。

调用 `AbilitySet->GiveToAbilitySystem(ASC)` 一行就能全部授予。

### ★★★★ InitState（初始化状态）

**Lyra 用来解决"组件启动顺序"问题的核心机制**。

一个 Pawn 身上可能挂 10 个组件（HeroComponent、AbilitySystem、Input、Camera...），它们之间有依赖关系（Input 得等 ASC 就绪才能绑按键）。InitState 是一个**状态机**：每个组件经过几个阶段：

```
NONE → Spawned → DataAvailable → DataInitialized → GameplayReady
```

一个组件必须等另一个组件到达某个状态才能前进，由 `ULyraPawnExtensionComponent` 统一协调。

文件：[LyraPawnExtensionComponent](../Source/LyraGame/Character/LyraPawnExtensionComponent.h)

**为什么重要**：这个机制让你写的新组件可以"插队"到现有流程里，不破坏顺序。第 05 章会详细讲。

### ★★★ GameFeatureAction（功能动作）

GameFeature 激活时要执行的"动作"。每个 Action 就是一个 C++ 类，重写 `OnGameFeatureActivating` / `OnGameFeatureDeactivating`。

Lyra 自带的 Action：

- `GameFeatureAction_AddAbilities` —— 往所有符合条件的 Pawn 身上加能力。
- `GameFeatureAction_AddInputContextMapping` —— 启用某个输入映射。
- `GameFeatureAction_AddWidget` —— 往 HUD 加某个 Widget。

路径：[Source/LyraGame/GameFeatures/](../Source/LyraGame/GameFeatures/)

### ★★★ GameplayMessage（游戏消息）

Lyra 的**事件总线 / 发布订阅系统**。

任何代码都可以：

- **发布**：带一个 Tag 和一个结构体。
- **订阅**：监听某个 Tag 的消息。

发布者和订阅者互相不认识，只共享 Tag。

插件：[Plugins/GameplayMessageRouter/](../Plugins/GameplayMessageRouter/)
常用消息类型：[LyraVerbMessage](../Source/LyraGame/Messages/LyraVerbMessage.h)

**举例**：玩家击杀敌人 → 能力系统发布 `Message.Player.Eliminated` 消息 → UI / 音效 / 计分板各自订阅并响应。

### ★★★ CommonUI

UE 官方的现代 UI 框架。Lyra 用它来构建所有 UI。

核心概念：

- **ActivatableWidget**：可激活的 Widget，能堆叠（像浏览器 Tab）。
- **Widget Stack**：UI 栈。按 ESC 返回上一层。
- **输入路由**：自动处理"UI 抢输入 vs 游戏接收输入"。

Lyra 基类：[LyraActivatableWidget](../Source/LyraGame/UI/LyraActivatableWidget.h)

### ★★★ WorldSettings（世界设置）

关卡自身的配置。Lyra 扩展了 `WorldSettings`，让每个关卡可以声明"**这个关卡默认用哪个 Experience**"。

类：[LyraWorldSettings](../Source/LyraGame/GameModes/LyraWorldSettings.h)

这是 `HandleMatchAssignmentIfNotExpectingOne` 确定 Experience 的默认来源之一（下一章详讲）。

### ★★★ AssetManager / PrimaryAssetId

UE 原生系统。`PrimaryAssetId` 是资产的"身份证"（`类型名 + 资产名` 组成的二元组）。`AssetManager` 负责按 ID 加载资产，并管理资产的生命周期和引用计数。

Experience、PawnData 这些都是 Primary Asset。Lyra 大量用 `FPrimaryAssetId` 来引用资产，而不是直接的硬引用 `UObject*`。

Lyra 扩展版：[LyraAssetManager](../Source/LyraGame/System/LyraAssetManager.h)

## 四、读一段真实代码试试

把术语学完了，我们来读一小段代码验证一下。这是你在 02 章就会深入的 [LyraGameMode.cpp:88-165](../Source/LyraGame/GameModes/LyraGameMode.cpp#L88) 的核心片段（简化版）：

```cpp
// 没有匹配分配时，自行按优先级决定加载哪个体验：
// URL 参数(Experience=) → 开发者设置(PIE) → 命令行 → 关卡 WorldSettings → 默认体验/专用服务器登录
void ALyraGameMode::HandleMatchAssignmentIfNotExpectingOne()
{
    FPrimaryAssetId ExperienceId;  // [术语 15] 资产 ID
    // ... 按优先级决定用哪个 Experience ...
  
    // 从 WorldSettings 读默认 Experience
    if (ALyraWorldSettings* TypedWorldSettings = Cast<ALyraWorldSettings>(GetWorldSettings()))
    {
        ExperienceId = TypedWorldSettings->GetDefaultGameplayExperience();  // [术语 14]
    }
  
    // 最后的兜底：硬编码默认 Experience
    if (!ExperienceId.IsValid())
    {
        ExperienceId = FPrimaryAssetId(
            FPrimaryAssetType("LyraExperienceDefinition"),  // [术语 1]
            FName("B_LyraDefaultExperience"));
    }
  
    OnMatchAssignmentGiven(ExperienceId, ExperienceIdSource);
    // 这会调用 ExperienceComponent->SetCurrentExperience(ExperienceId)
    // ExperienceComponent 会加载 Experience，激活它声明的所有 GameFeature [术语 2]
    // GameFeature 激活时会执行 GameFeatureAction [术语 11] 把能力、UI、输入注入世界
}
```

如果这段你能大致看懂"它在按优先级找一个 `ExperienceId`，然后交给 ExperienceComponent 去加载"，你就过关了。

**如果看不懂**，不是你笨，是你需要回去把"★★★★★"的五个术语再看一遍。

**练习 01.1**：打开 [Source/LyraGame/LyraGameplayTags.h](../Source/LyraGame/LyraGameplayTags.h)，扫一眼它声明了多少 Tag。你不用理解每一个，只需感受一下"Lyra 有多少种 Tag"。

**练习 01.3**：打开 `Plugins/GameFeatures/ShooterCore/` 目录，**感受**一下一个 GameFeature 插件的组成（`.uplugin` 文件 + `Content/` 资产 + 可选的 `Source/` 代码）。

**练习 01.4**（思考题，不要写代码）：如果你想给 Lyra 加一个"低重力模式"：跳跃高度变为 3 倍、移动速度变慢、子弹变慢。你会：

- 新建一个 Experience？
- 还是新建一个 GameFeature？
- 还是两者都要？
- 会不会动 `ALyraCharacter` 的代码？

想清楚再看下面的参考答案（**别偷看**）。

<details>
<summary>参考答案</summary>

**理想方案**：新建一个 GameFeature 插件 `LowGravityMode`，里面包含：

- 一个 `GameFeatureAction_AddAbilities`，给玩家加一个"低重力 Ability"（这个 Ability 挂一个 `GameplayEffect` 修改移动相关属性）。
- 一个新的 Experience `B_Experience_LowGravity`，它基于默认 Experience，但激活列表里多了这个 GameFeature。

**不要**动 `ALyraCharacter` 的代码——跳跃高度和移动速度都是可以通过 GameplayEffect 修改的 Attribute（在 `LyraMovementSet` 里）。

这就是 Lyra 架构的威力：**玩法变化 = 数据变化**，**代码纹丝不动**。
