## 一、把项目跑起来

### 1.1 引擎版本对齐

打开 [LyraStarterGame.uproject](../LyraStarterGame.uproject)，顶部应该有 `"EngineAssociation": "5.7"` 之类的字段。你需要 UE 5.7 的 **源码版或 Launcher 版**。

如果你装的是不同版本，有两条路：

- **简单路**：升级/降级引擎版本到 5.7。
- **难路**：改 `EngineAssociation`，然后修若干 API 变更——新手别走这条。

### 1.2 生成 VS 项目文件

右键 `.uproject` → `Generate Visual Studio project files`（或 Rider 的 `Generate Project Files`）。**不要手动编辑 .sln**，每次修改 uproject / 模块文件后都要重新生成。

### 1.3 编译

打开生成的 `.sln`，选择 **`Development Editor | Win64`**，Build → Build Solution。

**首次编译可能 15-40 分钟**，泡个茶。

### 1.4 运行

- 编译完成后，Start Debugging (F5) 打开 Lyra 编辑器。
- 编辑器打开后，默认关卡是 `L_LyraFrontEnd`（主菜单）。
- 按 **Alt+P** 进入 PIE（Play In Editor）。
- 菜单里有几个按钮：`Play Lyra` / `TopDown Arena` / `Elimination` / `Horde Mode`... 每个按钮点进去都是不同的玩法——这些玩法的"配置"就叫 **Experience**（下一章会详细讲）。

### 1.5 关掉加载时的"广告"弹窗

Lyra 自带一个在线登录流程，开发环境下你可能会看到"登录 Epic 账户"之类的提示。

打开 [Config/DefaultGame.ini](../Config/DefaultGame.ini) 搜索 `bAutoLogIn`，需要时可临时禁用。（不是重点，先跑起来就行。）

## 二、把"代码地图"印进脑子

你第一次打开 `Source\LyraGame` 会懵，因为有十几个子目录。**不要试图一口气看完所有目录**。你先记住下面三条"航线"：

### 航线 A：游戏启动链（本 Wiki 第 02 章讲）

```
LyraGameMode.cpp::InitGame()
    → HandleMatchAssignmentIfNotExpectingOne()  (决定加载哪个 Experience)
    → ExperienceManagerComponent->SetCurrentExperience()
    → (Experience 加载完) → OnExperienceLoaded()
    → 生成 Pawn，玩家可以动了
```

### 航线 B：开火链（本 Wiki 第 11 章讲）

```
按键 (IA_Shoot)
    → LyraInputComponent 调用绑定的 AbilityTag
    → LyraAbilitySystemComponent 激活 Ability_RangedWeapon
    → Ability 做射线检测 → 命中 → 发 GameplayEffect
    → 敌人的 HealthAttribute 减少 → 触发死亡 Cue
```

### 航线 C：UI 显示链（本 Wiki 第 14 章讲）

```
LyraHUD::BeginPlay
    → 读 HUDLayout → 创建 CommonUI Widget
    → Widget 订阅 GameplayMessage（血量变化）
    → 属性变化 → 消息广播 → UI 刷新
```

**这三条航线就是本 Wiki 的骨架**。其他系统（装备、相机、队伍）都是从这三条航线上长出来的分支。

## 三、读代码的六条心法

这些是"学 Lyra 特有"的心法，不是通用读代码技巧。**违反其中任何一条，你都会多走弯路。**

### 心法 1：**不要线性读代码**，要沿着一次"运行事件"追调用链

错误姿势：从 `LyraGameMode.h` 第一行读到最后一行，再读 `LyraGameState.h`...

正确姿势：**问一个问题，跟着代码找答案**。比如"Lyra 是怎么决定玩家用哪个 Pawn 类的？" → 追 `GetDefaultPawnClassForController` → 追到 `GetPawnDataForController` → 发现依赖 Experience → 于是去读 Experience。

每次追调用链都会把**相关的几个类一起学会**，比单独背一个类的所有方法有效十倍。

### 心法 2：**GameplayTag 是导航仪**

Lyra 大量用 `GameplayTag` 做"弱耦合引用"。你会看到这种代码：

```cpp
if (AbilitySystemComponent->HasMatchingGameplayTag(LyraGameplayTags::Status_Death))
```

遇到陌生的 `Tag`，**全局搜这个 Tag 的名字**（比如 `Status_Death` 或 `"Status.Death"`），你能看到：

- 谁给角色加上这个 Tag（发生死亡时）
- 谁检查这个 Tag（动画系统、UI、队友 AI）

**比追类继承树高效十倍**，因为 Tag 本身就是系统之间的契约。

### 心法 3：**Experience 是一切的入口**

Lyra 和普通 UE 项目最大的差异就是：**几乎所有玩法内容都不是硬编码到 GameMode 的**，而是装在一个叫 `ULyraExperienceDefinition` 的资产里。

读到任何一个"这个角色怎么有这个能力？"、"这个 UI 怎么会出现？"、"这个按键怎么绑的？"的问题，**先去 Experience 里看它挂了什么 Action**。

这个心法贯穿后面 16 章。

### 心法 4：**看 .h 之前先看对应的 .cpp 开头**

Lyra 的 `.h` 里常常只是声明，**真正的业务流在 .cpp 的 `InitializeComponent()` / `BeginPlay()` / `OnExperienceLoaded()` 里**。

打开一个陌生类时，先扫它 cpp 的这几个"生命周期回调"，能最快看出这个类在运行时干什么。

### 心法 5：**边读边写笔记**

每读完一个章节（或系统），花 15 分钟用你喜欢的工具（PlantUML / Mermaid / 纸笔）画一张：

- **时序图**（对于调用链）
- **类图**（对于静态关系）

画图的过程会暴露你理解上的漏洞：画到一半卡住，说明那个地方其实没看懂。

推荐工具：

- [Mermaid Live Editor](https://mermaid.live/) — 文本即图，好管理。
- 纸笔 — 便携而且不会诱惑你刷其他东西。

### 心法 6：**不要靠 AI 解释代码取代读源码**

你可以问 AI："Lyra 的 Experience 系统大概是什么设计？"，但**不要**问"请帮我逐行解释这个文件"然后就完事了。

Lyra 的设计精妙处在**字里行间的细节**（比如为什么 `TimerManager().SetTimerForNextTick`，为什么 `ExperienceComponent` 放在 GameState 而不是 GameMode）。这些细节 AI 能大致对，但要真的吸收成自己的设计直觉，**必须亲眼看着源码想清楚**。

把 AI 当"辅助翻译官"用：看不懂某个 UE API 可以问，但**理解架构这件事交给你自己**。

## 四、工具链推荐

在正式开读前，把这些装好：

| 工具                                  | 用途                                               | 必要性     |
| ------------------------------------- | -------------------------------------------------- | ---------- |
| Visual Studio 2022 或 JetBrains Rider | C++ IDE                                            | ★★★★★ |
| Unreal Insights                       | 性能分析、Trace 游戏一帧到底在干啥                 | ★★★★   |
| Visual Logger                         | 看 AI / 技能 / 战斗的运行时轨迹                    | ★★★★   |
| GameplayDebugger                      | PIE 里按`'` 键调出，实时看 ASC / 属性 / Tag 状态 | ★★★★★ |
| Mermaid 编辑器                        | 画图做笔记                                         | ★★★     |
| Obsidian / Notion                     | 做自己的学习笔记本                                 | ★★★     |

**这些工具后面每章都会用到**。现在只要知道有这些东西、怎么打开即可。

## 五、动手练习

**练习 00.1**：把项目跑起来，进入 `Play Lyra` 模式，在场景里走动、开火。

**练习 00.2**：打开 `L_LyraFrontEnd` 关卡，在内容浏览器里找到 "Maps" 或 "Experiences" 目录，随便打开一个 `.uasset` 文件扫一眼——你看不懂是正常的，感受它"有一堆字段"就够了。

**练习 00.3**：在 PIE 模式下按 `'` 键调出 GameplayDebugger，按数字键 1/2/3/4 切不同分类，观察屏幕上的调试信息。你暂时不必理解每个字段，但要记住"这个工具存在"。

**练习 00.4**：在 VS Code 里打开 [Source/LyraGame/GameModes/LyraGameMode.h](../Source/LyraGame/GameModes/LyraGameMode.h)，通读一遍所有方法名（不看实现）。这就是整个游戏的"入口"。你应该能看到 `InitGame` / `OnExperienceLoaded` / `HandleMatchAssignmentIfNotExpectingOne` 这些词——下一章我们就从这里开始。
